Welcome to PRM

PRM (Project & Resource Management) is a comprehensive tool for managing projects, sprints, tasks, resources, and capacity planning across multiple development teams.

Key Capabilities
  • Project & Module Management — Organize work into Projects → Modules → Sub Modules
  • Task Tracking — Create tasks with activity logs, attachments, status tracking
  • Resource Calendar — Daily/Weekly/Monthly view of time spent per resource (8h/day capacity)
  • Utilization Tracking — Sprint-based capacity and utilization grid
  • Leave & Holiday Management — Track leaves and holidays that reduce capacity
  • Dynamic Role-Based Access — Control page visibility per role via Page Access settings
  • Integrations — MS Teams notifications, Salesforce sync, SMTP email, Azure Blob storage

Quick Start Guide

Get up and running in 5 minutes. Follow these steps in order.

Initial Setup Steps
Define Roles & Capacity — Go to Admin → Role Capacity. Add roles (e.g., Developer = 192 hrs, Lead = 96 hrs).
Add Skills — Go to Admin → Skills. Add skill categories (Backend, Frontend, QA, etc.).
Create Task Statuses — Go to Admin → Task Status. Add statuses like Not Started, In Progress, Completed.
Create a Project — Go to Admin → Projects. Add your first project with a code and dates.
Create Modules — Go to Admin → Modules. Add modules under your project, then sub-modules.
Add Work Types — Go to Admin → Work Types. Define types like New Requirement, Bug Fix, etc.
Create Sprints — Go to Admin → Sprints. Define monthly sprint periods.
Add Users/Resources — Go to Admin → User Setup. Add team members (resource code auto-generates as RES100, RES101, etc.).
Set Page Access — Go to Admin → Page Access. Control which roles can see which pages.
Start Creating Tasks! — Go to Tasks page and start tracking work.
Pro Tip Default password for new users is Ids@1001. Users can change it after first login.

Roles & Permissions

PRM uses a dynamic role system. Roles are defined on the Role Capacity page and access is controlled via Page Access.

How Roles Work
  • Roles are created in Admin → Role Capacity (e.g., Developer, Lead, Manager)
  • Each role has a default capacity in hours/month
  • Page visibility is controlled in Admin → Page Access
  • If a role has access to any admin page, it gets admin-level API permissions
  • Admin always has full access to Settings and Page Access (cannot be revoked)
Important When you create a new custom role (e.g., "Development Manager"), make sure to grant it page access in the Page Access settings — otherwise it won't see any admin pages.

Page Access Control

Control which roles can see each page in the sidebar menu. Admin Only

Page Access — Role × Page matrix
How It Works
  • Grid: Rows = pages, Columns = roles (from Role Capacity)
  • Check/uncheck boxes to grant or revoke access
  • Admin always keeps access to Settings and Page Access
  • Changes take effect on next page load
  • If a role has admin page access, it also gets API-level admin permissions
Important If no page access rules are saved (first time), all pages are visible to all roles (backward compatible).
